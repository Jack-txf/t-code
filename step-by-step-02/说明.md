# step-by-step-02：MCP 架构升级说明

## 目标

在 step-by-step-01 的基础上，将**本地函数式工具**升级为**MCP（Model Context Protocol）协议式工具**，理解 Agent 与工具之间的标准化通信方式。

## 核心概念

### 1. MCP Server（`mcp-server.py`）

使用 `mcp` 包提供的 `FastMCP` 高层次 API：

- `@mcp.tool()` 装饰器自动将 Python 函数注册为 MCP 工具，并生成 JSON Schema。
- `mcp.run(transport="stdio")` 启动 Server，监听 stdin 上的 JSON-RPC 请求，结果写入 stdout。

Server 启动后不做任何事，只等待 Client 连接并发送指令。

### 2. MCP Client（`simple-agent-mcp.py`）

Client 负责三件事：

1. **建立连接**
   ```python
   server_params = StdioServerParameters(
       command=sys.executable,
       args=["step-by-step-02/mcp-server.py"],
   )
   async with stdio_client(server_params) as (read, write):
       async with ClientSession(read, write) as session:
           await session.initialize()
   ```
   Client 将 `mcp-server.py` 作为子进程启动，双方通过 stdin/stdout 通信。

2. **发现工具**
   ```python
   tools_result = await session.list_tools()
   ```
   返回的工具需要转换为 OpenAI Function Calling 格式才能传给 LLM。

3. **执行工具**
   ```python
   result = await session.call_tool(name, arguments)
   ```
   结果在 `result.content` 中（列表形式），需要拼接为字符串。

### 3. 格式转换（桥接层）

MCP 协议的工具描述格式与 OpenAI Function Calling 格式不同，需要在 Client 中做一次转换：

| MCP 字段 | OpenAI 字段 |
|---------|------------|
| `tool.name` | `function.name` |
| `tool.description` | `function.description` |
| `tool.inputSchema` | `function.parameters` |

转换函数：`mcp_tools_to_openai()`

## 运行方式

确保在项目根目录（`t-code/`）执行，且 `.env` 文件已配置：

```bash
source .venv/Scripts/activate
python step-by-step-02/simple-agent-mcp.py
```

程序启动后会自动拉起 `mcp-server.py` 子进程，你应该能看到类似输出：

## 为什么要这样做？

step-by-step-01 的本地函数方式虽然简单，但有明显局限：

1. **工具与 Agent 强耦合**：想加新工具必须改 Agent 代码。
2. **没有复用标准**：每个 Agent 框架都有自己的工具注册方式。
3. **隔离性差**：工具函数出错可能拖垮整个 Agent 进程。

MCP 解决以上问题：
- Agent 不需要知道工具的具体实现，只通过协议交互。
- 任何语言编写的 MCP Server 都能被这个 Agent 使用（Python、Node.js、Rust 等）。
- 工具运行在独立进程，崩溃不影响 Agent。
- Anthropic、Cursor、Claude Desktop 等产品已原生支持 MCP，掌握这套协议意味着你的 Agent 可以无缝接入生态。
